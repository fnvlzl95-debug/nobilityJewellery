# 귀족 가이드 관리

귀족 웹사이트의 `/guide` 콘텐츠를 분석하고 생성한 뒤 검수 승인을 거쳐 로컬 저장소에 반영하는 전용 도구입니다.

## 실행

1. `시작.bat`을 실행합니다.
2. 브라우저에서 `http://127.0.0.1:8788`을 엽니다.
3. 첫 실행 시 청소업체블로그관리 프로젝트의 OpenAI/Naver 설정과 Downloads 폴더의 분석 파일을 안전하게 가져옵니다.

`8788`을 다른 로컬 프로그램이 사용 중이면 `시작.bat`은 잘못된 화면을 여는 대신 중단하고 안내합니다. 해당 프로그램을 닫은 뒤 다시 실행하세요.

## 작업 흐름

1. 성과 현황과 기회 탐색에서 근거를 확인합니다.
2. 가이드 편집에서 Naver 검색 의도와 공식 출처를 조사하고 사용할 출처를 승인합니다.
3. Luna 초안을 만들고 필요할 때 Terra 재생성, Humanizer V9, 이미지 작업실을 사용합니다.
4. 품질 검사와 파일 diff를 확인한 뒤 최종 승인합니다.
5. `저장소에 반영`을 눌렀을 때만 귀족 저장소가 바뀌며, 형 검사·빌드·SEO 검사 실패 시 이번 변경만 복원됩니다.

반영 이력에서 실제 배포일·커밋을 기록하면, 배포 다음 날 이후의 동일 길이·동일 보고서만 참고 변화로 비교합니다. 오래된 자료의 재수입은 사후 성과로 인정하지 않습니다. 상담 성과 화면에는 개인정보 없이 유입 가이드와 상담 단계를 기록합니다.

기존 글 진단의 `현재 원문 유지·성과 관찰`은 편집 작업을 만들지 않습니다. 낮은 노출이나 높은 이탈률만으로 원고를 다시 쓰지 않으며, 기본 일괄 정밀진단도 구체적인 수정 항목이 있는 글을 대상으로 합니다. 추가 근거가 필요하면 해당 글의 정밀진단을 명시적으로 실행할 수 있습니다. 최근 변경일의 D+31 관찰과 보호 가이드 제한은 그대로 적용됩니다.

사이트 전체 GSC 검색어는 참고 자료입니다. 페이지별 검색어 연결이 확인되지 않으면 그 검색어를 제목에 넣는 자동 수정은 보류합니다. 페이지의 CTR이 낮다는 진단과 실제 제목을 바꿀 근거는 구분합니다. 현재 앱은 페이지 필터 자료의 자동 연결을 지원하지 않습니다. Search Console에서 해당 URL·기간의 검색어를 확인한 뒤 가이드 편집의 `기존 글 수정 → 검색 제목·설명`에서 원문과 대조할 수 있으며 기존 성과·관찰 보호는 유지됩니다.

진단 계획에 출처 URL 보존 지시가 있으면 기존 URL·설명·순서를 유지하면서 선택·검토한 새 출처를 추가합니다. 출처 목록 전체 보존을 명시하면 새 항목도 추가하지 않습니다. 이미 생성된 편집 작업의 수정 범위는 자동으로 넓히지 않으므로, 예전 잠금 규칙이 저장된 작업은 최신 계획으로 다시 생성해야 합니다.

## 안전 범위

- 외부 접속을 받지 않고 `127.0.0.1`에만 바인딩합니다.
- 사용자의 승인 전에는 귀족 저장소를 수정하지 않습니다.
- 반영 후 형 검사·빌드·SEO 검사를 모두 통과해야 변경을 유지합니다.
- Git 커밋, 푸시, 배포는 하지 않습니다.
- 커스텀 가이드 2개는 읽기 전용입니다.


## 버전 관리와 배포

공개 사이트 저장소의 `tools/guide-manager`가 관리 도구 소스 원본입니다. `npm ci`, `npm test`, `npm run build`로 검증한 뒤 `scripts/deploy-local.ps1`로 바탕화면 앱에 반영합니다. 데이터와 API 키는 Git에 넣지 않습니다. `GUIDE_MANAGER_DATA_DIR`로 별도 데이터 폴더를 지정할 수 있습니다.

테스트는 매번 임시 DB를 만들며 운영 DB를 사용하지 않습니다. 분석 통합 테스트의 기존 원본 CSV·ZIP은 `DOWNLOADS_DIR`에 준비합니다. 공개 사이트의 최신 `verify:seo`는 고정된 Wrangler로 Cloudflare 로컬 런타임을 실행합니다.
