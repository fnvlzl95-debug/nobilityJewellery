# 귀족 가이드 관리

귀족 웹사이트의 `/guide` 콘텐츠를 분석하고 생성한 뒤 검수 승인을 거쳐 로컬 저장소에 반영하는 전용 도구입니다.

## 실행

1. `시작.bat`을 실행합니다.
2. 브라우저에서 `http://127.0.0.1:8788`을 엽니다.
3. 첫 실행 시 청소업체블로그관리 프로젝트의 OpenAI/Naver 설정과 Downloads 폴더의 분석 파일을 안전하게 가져옵니다.

`8788`을 다른 로컬 프로그램이 사용 중이면 `시작.bat`은 잘못된 화면을 여는 대신 중단하고 안내합니다. 해당 프로그램을 닫은 뒤 다시 실행하세요.

## 작업 흐름

1. 성과 현황과 기회 탐색에서 근거를 확인합니다.
2. 가이드 편집에서 Naver 검색 의도와 공식 출처를 조사하고, 원문과 연결된 주장을 대조해 사용할 출처를 검토합니다.
3. Luna 초안을 만들고 필요할 때 Terra 재생성, Humanizer V9, 이미지 작업실을 사용합니다.
4. 출처 검토 기록, 구조·정책 검사와 파일 diff를 확인한 뒤 최종 승인합니다.
5. `저장소에 반영`을 눌렀을 때만 귀족 저장소가 바뀌며, 형 검사·빌드·SEO 검사 실패 시 이번 변경만 복원됩니다.

반영 이력에서 실제 배포일·커밋을 기록하면, 배포 다음 날 이후 완료된 동일 길이·동일 보고서의 겹치지 않는 기간을 참고 변화로 비교합니다. GSC는 태평양 시간(PT)과 동일 속성·검색 범위를 확인하며, GA4는 원본에 시간대 메타가 없어 한국 시간(KST)을 가정합니다. 화면에서 플랫폼별 변경 전·배포 후 기간, 자료 ID와 시간대 가정 여부를 각각 확인하세요. 오래된 자료의 재수입은 사후 성과로 인정하지 않습니다. 상담 성과 화면에는 개인정보 없이 유입 가이드와 상담 단계를 기록합니다.

기존 글 진단의 `현재 원문 유지·성과 관찰`은 편집 작업을 만들지 않습니다. 낮은 노출이나 높은 이탈률만으로 원고를 다시 쓰지 않으며, 기본 일괄 정밀진단도 구체적인 수정 항목이 있는 글을 대상으로 합니다. 추가 근거가 필요하면 해당 글의 정밀진단을 명시적으로 실행할 수 있습니다. 최근 변경일의 D+31 관찰과 보호 가이드 제한은 그대로 적용됩니다.

사이트 전체 GSC 검색어는 참고 자료입니다. 특정 글의 제목 검토에는 해당 URL로 정확히 필터한 페이지별 검색어 자료를 사용합니다. CTR이 낮거나 검색어가 연결됐다는 사실만으로 제목 결함이나 개선 효과를 판정하지 않습니다.

### 출처 원문 검토

`출처` 탭에서 문서 링크를 열고 표시된 조사 주장과 실제 원문을 대조합니다. 사용할 출처를 선택한 뒤 문서 제목·절·문단 등 **확인 위치**, 적용 조건이나 예외를 포함한 **대조 메모**, **직접 확인 표시**를 함께 저장하세요. 모델의 확신도와 공식 도메인 여부는 운영자의 문서 검토를 대신하지 않습니다.

자동 준비가 선택한 출처는 `자동 조사 선택 · 운영자 문서 대조 전` 상태입니다. 초안 작성은 가능하지만 새 작업의 최종 승인·반영에는 운영자 검토 기록이 필요합니다. 출처 URL·문서 설명이나 연결된 주장이 바뀌면 이전 확인은 만료되어 다시 검토해야 합니다. 이미 반영된 작업의 검토 기록은 소급해서 바꾸지 않습니다.

`구조·정책 검사` 점수는 원고 형식과 정해진 규칙을 확인한 결과입니다. 사실 정확성, 검색 순위·노출·클릭 개선을 검증한 점수가 아니므로 원문 대조와 최종 검수를 별도로 수행합니다.

### 페이지별 검색어를 실제 수정에 연결하기

1. Search Console 웹검색 실적에서 `페이지 → 정확한 URL`을 선택합니다. 사이트 전체 보고서와 같은 기간을 지정하고 국가·기기·검색어 등의 추가 필터 없이 전체 보고서를 ZIP으로 내보냅니다.
2. `분석 자료`에서 `특정 글의 페이지별 검색어 연결`을 선택하고 파일·URL·시작일·종료일을 입력합니다. 실제 필터와 전체 내보내기를 확인한 뒤 가져옵니다. 원본 파일과 해시는 그대로 보관하며, 입력한 확인 내용이 파일의 URL·기간·필터와 다르면 거부합니다.
3. `기존 글 진단`에서 `수치 다시 계산`을 실행합니다. 현재 사이트 전체 보고서와 속성·기간이 일치하는 정확한 URL의 자료만 연결됩니다. 페이지 자료는 사이트 전체 추천과 배포 전후 비교를 덮어쓰지 않습니다.
4. 해당 글의 검색어·페이지 실적·원문을 대조합니다. 공개된 검색어가 0행이면 검색 수요도 0이라는 뜻이 아닙니다. 검토 후보는 최신 자료와 내용 관련성으로 선별하며 Google 기준이나 통계적 효과 판정이 아닙니다.
5. 실제 불일치가 있을 때만 관련 검색어를 선택하고 확인한 문제를 적습니다. 제목·설명을 직접 교정하고 검토를 확인한 뒤 해당 항목을 선택합니다. 원문과 같은 교정안은 작업을 생성하지 않습니다.
6. 이 제목 교정은 입력한 문구를 바로 검토 초안으로 엽니다. 본문·출처·이미지는 보존하고 유료 자동 조사·재작성 없이 검사·변경 비교·승인으로 진행합니다. 출처 등 다른 수정은 별도 계획으로 검토합니다.

자료 교체·측정 기간 변경·원문 변경은 생성·저장·승인·반영 시 다시 확인합니다. 페이지별 자료를 가져와도 D+31 관찰과 기존 성과 제목 보호는 해제되지 않습니다. 변경한 글은 실제 배포일을 기록한 뒤 같은 길이·같은 보고서로 결과를 관찰해야 합니다.

진단 계획에 출처 URL 보존 지시가 있으면 기존 URL·설명·순서를 유지하면서 선택·검토한 새 출처를 추가합니다. 출처 목록 전체 보존을 명시하면 새 항목도 추가하지 않습니다. 이미 생성된 편집 작업의 수정 범위는 자동으로 넓히지 않으므로, 예전 잠금 규칙이 저장된 작업은 최신 계획으로 다시 생성해야 합니다.

### 대조 글과 함께 관찰하기

`대조 글 관찰`에서 실제 배포일을 기록한 **기존 글 수정**을 선택하고, 비슷한 주제·기존 노출을 가진 유지 대상 글을 지정합니다. `원문과 비교 조건 확인`을 누른 뒤 선정 이유와 두 글의 차이를 기록해 등록하세요. 원문·목록 지문, 변경 전 자료와 배포 기록을 보존하며 등록한 대조 글을 덮어쓰지 않습니다.

관찰 기간은 **배포 다음 날부터 시작하는 첫 번째 기간**으로 고정하며 길이는 변경 전 보고서와 같습니다. 플랫폼별로 두 글에 동일한 원본 보고서 ID를 사용합니다. 고정 기간과 실제 사용한 원본의 기간·ID를 구분해서 확인하세요. 더 늦은 보고서나 다른 속성의 자료로 이 기간을 대체하지 않습니다.

관찰 중 대상·대조 글의 원문·목록이 바뀌거나 기준 자료가 바뀐 경우, 관찰 기간이 시작된 뒤 대조 글을 선정한 경우에는 자동 변화 비교를 보류합니다. 관찰 종료 뒤 커밋된 수정은 완료한 기간을 무효화하지 않지만 시각을 확인할 수 없는 미커밋 변경은 보류합니다. Git 커밋 시각은 실제 공개 배포 시각의 증명이 아닙니다. 누락은 `미확인`이고 실제 0과 다릅니다. 이는 무작위 실험이 아닌 참고 관찰이며, 변화 차이를 수정의 인과효과나 입증된 검색 상승으로 해석하지 않습니다. 상담·비용도 자동 합산하지 않습니다.

### 문의 접수번호와 상담 기록 연결하기

`상담 성과`의 선택 접수번호에 온라인 문의 이메일의 **NG-… 번호를 그대로** 입력합니다. 유입 가이드를 확인한 뒤 상담일·현재 단계를 저장하고, 단계가 바뀌면 같은 번호의 기존 항목을 선택해 수정하세요. 전화·카톡 상담처럼 접수번호가 없으면 무작위 UUID를 만들며 이름·전화번호는 입력하지 않습니다.

저장 응답이 끊겨도 같은 화면의 재시도는 같은 번호를 사용합니다. 오류 후 기존 목록을 다시 조회하고 저장 확인용 번호를 보여 줍니다. 이미 저장된 번호의 내용을 바꾸려면 목록에서 해당 상담을 선택하세요. **다른 상담**을 기록할 때만 `다른 새 상담으로 전환`을 사용합니다. 공개 문의 이메일을 자동으로 읽어 등록하는 기능은 아닙니다.

### 임시 원고와 반영 후 진단

`구조 JSON 편집`의 미완성 입력도 작업별로 브라우저에 임시 보관하며 미저장 상태에 포함합니다. 글 전환·새로고침 후 복원하고, 기준 revision이 달라졌으면 최신 원고와 비교하기 전 저장·승인·반영을 막습니다. 일반 원고 저장이 별도의 미저장 JSON을 지우지 않습니다. `JSON 저장·재검사` 또는 명시적인 `JSON 입력 폐기`로 정리하며, 임시 보관 공간 오류가 나면 입력을 복사해 보관하세요.

저장소 반영을 완료하면 진단을 갱신 대상으로 표시하고 **다음 진단 조회**에서 원문·보호 기간·문맥을 다시 계산합니다. 자동 갱신은 새 AI 정밀진단을 실행하거나 분석 보고서를 새로 가져오는 작업이 아닙니다. 갱신 예약 경고가 나오면 `기존 글 진단 → 수치 다시 계산`을 실행하세요.

### 제작 운영 지표

성과 현황에서 최근 **7일·28일·90일**의 제작 지표를 확인합니다. 각 비율의 분자·분모와 기록 시작 시점을 함께 보며, 표본이나 분모가 없으면 값을 만들지 않습니다.

- **작업 시간 p50·p95:** 성공한 백그라운드 작업의 시작부터 종료까지를 작업 종류별로 계산합니다. 대기열과 사람의 검토 시간은 제외합니다.
- **자동 보완률:** 자동 초안·보완 호출이 기록된 작업 중 Luna 보완 또는 Terra 대체 호출이 있었던 비율입니다. 수동 편집률이 아닙니다.
- **중복 거절률:** 계측 시작 이후 직접 생성·기존 글 수정 생성 API 요청 중 동일 의도로 거절된 비율입니다. 자동 준비 내부 생성은 제외하며 재시도는 별도 요청입니다. 과거 미계측 기간을 0건으로 해석하지 않습니다.
- **범위 변경 거절률·반영 실패율:** 각각 저장·승인 요청 중 선택 범위를 벗어나 차단된 비율, 종료된 실제 반영 시도 중 자동 복원·복구 필요로 끝난 비율입니다. 차단되지 않은 범위 위반이나 모든 승인 작업의 실패율을 뜻하지 않습니다.
- **유효 상담당 제작 비용:** 실제 청구 비용·통화와 같은 기간의 유효 상담을 연결한 자료가 없어 `null`로 둡니다. 토큰이나 클릭을 비용·상담으로 환산하지 않습니다.

이 지표는 제작 과정의 병목과 재작업을 살피는 자료입니다. 검색 유입과 실제 문의·유효 상담은 별도로 관찰하며 단순 전후 차이를 인과효과로 단정하지 않습니다.

## 안전 범위

- 외부 접속을 받지 않고 `127.0.0.1`에만 바인딩합니다.
- 사용자의 승인 전에는 귀족 저장소를 수정하지 않습니다.
- 반영 후 형 검사·빌드·SEO 검사를 모두 통과해야 변경을 유지합니다.
- Git 커밋, 푸시, 배포는 하지 않습니다.
- 커스텀 가이드 2개는 읽기 전용입니다.


## 버전 관리와 배포

공개 사이트 저장소의 `tools/guide-manager`가 관리 도구 소스 원본입니다. `npm ci`, `npm test`, `npm run build`로 검증한 뒤 `scripts/deploy-local.ps1`로 바탕화면 앱에 반영합니다. 데이터와 API 키는 Git에 넣지 않습니다. `GUIDE_MANAGER_DATA_DIR`로 별도 데이터 폴더를 지정할 수 있습니다.

테스트는 매번 임시 DB를 만들며 운영 DB를 사용하지 않습니다. 분석 통합 테스트의 기존 원본 CSV·ZIP은 `DOWNLOADS_DIR`에 준비합니다. 공개 사이트의 최신 `verify:seo`는 고정된 Wrangler로 Cloudflare 로컬 런타임을 실행합니다.
