# 가이드 관리 요청 경로와 편집 무결성 보완

작성일: 2026-09-06 KST. 대상: `http://localhost:8788/`의 관리자 API. [앞선 측정 연결 보고서](guide-manager-measurement-loop-2026-09-06.md)에 이어 원보고서의 실행 1·3번, 중복 실행 차단과 다른 원고의 병행 저장 조건을 확인했다.

## 확인한 문제

Express 라우터는 대소문자·끝 슬래시가 다른 주소와 디코딩된 동적 ID를 처리하지만, 앞단의 원고 버전 검사와 작업 잠금은 요청 주소의 원래 문자열에 의존했다. 예를 들어 `/Generations/9/draft`는 저장 라우트에 도달하면서 `If-Match`와 `generation:9` 잠금 검사를 건너뛰었고, `/generations/10/apply/`는 전체 사이트 반영 잠금을 얻지 않았다. 실제 Express와 제품 미들웨어를 사용한 격리 재현으로 확인했다.

이는 세션 인증 우회가 아니다. 로컬 접근·Origin·세션 토큰 검사는 모든 쓰기에 먼저 적용된다. 유효한 관리자 요청 사이에서도 오래된 원고를 덮어쓰거나 같은 저장소에 동시 반영할 수 있는 무결성 문제다. 기존 회귀는 정상 UI가 사용하는 소문자 경로를 중심으로 검사해 이 별칭 경로를 놓쳤다.

## 수정 계약

- 보호 판단에 사용하는 경로의 대소문자와 끝 슬래시를 통일한다.
- 원고 ID는 Express와 같이 한 번 디코딩하고 실제 핸들러와 같은 숫자로 해석한다. 같은 양의 안전 정수 ID의 여러 표기는 같은 버전 검사·잠금·백그라운드 작업 식별자를 사용한다.
- 유효하지 않은 ID와 인코딩은 작업 실행 전에 거부한다. 실제 원고 slug와 요청 본문을 임의로 소문자 변환하지 않는다.
- 별칭 요청도 같은 제작 지표 동작으로 기록한다. 다른 원고의 저장, 기존 삭제, 자동 준비, 작업 UUID의 기존 계약은 유지한다.
