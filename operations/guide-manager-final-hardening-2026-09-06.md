404 원인은 정적 파일을 처리하는 경로와 Worker 경로의 차이였다. 가이드 첫 글자별 wildcard와 갤러리 경로는 Worker에서 제외돼 있었고, 최상위 404 파일이 없으면 Pages가 SPA로 간주해 홈 문서를 반환한다. 실제로 `/guide/nonexistent-audit-20260906`과 `/gallery/nonexistent-audit-20260906`은 홈 제목·H1·canonical과 함께 200을 반환했지만, Worker가 맡는 다른 누락 경로는 404였다. [Cloudflare의 404·SPA 동작 안내](https://developers.cloudflare.com/pages/configuration/serving-pages/)와 일치한다.

이번 보완은 누락 주소의 잘못된 성공 응답을 바로잡는다. 정상 글 107개의 색인 장벽을 새로 제거했다고 과장하지 않는다. 200은 색인을 보장하지 않으며, 실제로 존재하지 않는 페이지에는 404가 적절하다. [Google의 HTTP 상태 코드 안내](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes)
