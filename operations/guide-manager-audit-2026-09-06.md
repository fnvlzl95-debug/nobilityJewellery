# 귀족 가이드 관리 도구 전수 점검·개선 기록

대상: `http://localhost:8788/`, 바탕화면 `귀족가이드관리`의 Express·SQLite·React 소스, 연동된 `nobilityJewellery` Nuxt 사이트. 이전 공개 사이트 중심 보고서에 관리 도구 자체의 분석과 수정 사항을 보완한다.

## 결론

관리 도구는 실제로 사용된 시스템이다. 점검 당시 운영 DB에는 모델 호출 성공 370건·실패 13건, 활성 이미지 138개, 저장소 반영 성공 62건·복원 3건이 있었다. 이는 기능 사용 이력이며 매출 효과나 현재 외부 API의 성공을 증명하는 수치는 아니다.

가장 큰 문제는 반영 검증이 서버를 동기적으로 막는 구조, 외부 사이트에서 로컬 API에 변경 요청을 보낼 수 있는 구조, 자료를 가져온 날짜를 이용한 잘못된 전후 비교였다. 이 문제들과 연결된 편집 충돌·복구·데이터 최신성·문의 측정을 수정했다.

## 확인한 범위

- 서버: API 라우트, 설정·SQLite 스키마, 인벤토리, CSV/ZIP 분석 자료 가져오기, 추천 점수, 전수 진단, 주제 추천, 공식 근거 조사, 원고 생성, Humanizer, 이미지 생성·최적화, 린트, Vue 렌더러, 파일 반영·백업·기준선, 모델 평가.
- 관리 화면: 현황, 기회 탐색, 기존 글 진단, 편집 단계, 이미지, 분석 자료, 반영 이력, 설정 및 신규 상담 성과 화면.
- 사이트: 105개 가이드의 목록·페이지 연결과 공통 출력, 상담 경로, 이미지, 검색·페이지 이동, 문의 API, 이벤트 측정, 빌드 및 Cloudflare 라우팅.

## 공개 사이트와 연결해 수정한 사항

- 자기 도메인의 대표 이미지 주소를 Nuxt 이미지 최적화용 로컬 경로로 정규화했다. Open Graph 주소는 절대 주소를 유지한다.
- 모든 가이드에 상담 준비 안내를 제공한다. 관리 도구가 이후 생성하는 글도 같은 공통 컴포넌트를 사용한다.
- 금 무게 가이드의 상담 목적을 선택하면 상단·본문·상담 준비 문의의 유형이 함께 바뀐다.
- 계산기 사용은 페이지별 한 번 기록하며 중량 원값을 전송하지 않는다. 최종 문의 이벤트에는 가이드의 `source_path`를 연결했다.
- 클러스터 링크의 실제 클래스와 측정 코드를 일치시키고 도매·갤러리 링크를 포함했다.
- 가이드 검색을 추가하고 목록을 서버에서 렌더링한다. Cloudflare의 `/guide/*` 제외가 `/guide`까지 정적 처리하는 문제를 접두사별 제외로 해결했다. 상세 가이드는 계속 정적 제공한다.
- 검색·카테고리·페이지의 첫 HTML, canonical, robots를 로컬 Cloudflare 런타임에서 검사하도록 배포 검증을 확장했다.
- 모스 경도 가이드의 목록·본문 카테고리를 일치시켰다.
- 문의 전송에 안정된 요청 식별번호와 Resend 멱등성 키를 사용한다. 네트워크·일시 오류는 제한적으로 재시도하며 호출에 15초 제한을 둔다. 접수 확인 전에는 성공·리드 이벤트를 발생시키지 않는다.

## 효과를 판단하는 방법과 한계

기술적 효과는 테스트·초기 HTML·이미지 경로·오류 처리로 확인할 수 있다. 문의나 계약 증가 효과는 배포 이후 같은 기간의 새 자료와 실제 상담 기록이 있어야 판단할 수 있다. 예전 자료를 다시 가져오거나 새로고침하는 것으로 측정 기간이 갱신되지는 않는다.

반영 이력에서 **실제 배포 완료 시각과 배포 커밋**을 기록한다. GSC 기준선이 92일이면 같은 길이의 사후 자료가 필요하다. 여러 플랫폼의 클릭·사용자·이벤트를 더해 하나의 성과로 만들지 않는다. 상담 성과는 유입 가이드를 확인한 실제 상담만 기록하며 이름·전화번호를 넣지 않는다.

외부 AI·이미지 모델 전체를 유료로 재실행하거나 실제 문의 메일을 발송한 검증은 하지 않았다. 원고·Humanizer·이미지의 저장·검사 정책은 기존 이력과 테스트로 확인했다. 모델의 사실성은 출처 대조와 운영자 검토가 필요하다.

전송 실패가 장기간 이어질 때의 별도 영구 메시지 큐, 다중 서버 공유 속도 제한, 자동 계약 데이터 연동은 이번 로컬 관리 도구 배포에 포함하지 않는다. 문의 화면은 실패를 표시하고 원문을 유지한다. Resend의 멱등성 보관은 24시간이므로 이 범위를 넘는 요청을 같은 성공으로 간주하지 않는다.

기존 글의 참고 출처 보강과 클러스터 편입은 기존 글 진단의 수정 계획으로 검토할 수 있다. 전체 글에 임의의 근거·검토자·새 검토일을 일괄 추가하지 않았다. 상위 노출 글을 수정한 직후에는 기존 D+31 관찰 보호도 유지한다.

## 실행·재현

사이트에서 `npm run typecheck`, `npm run test:measurement`, `npm run build`, `npm run verify:seo`를 실행한다. 마지막 검사는 임시 Cloudflare 로컬 런타임도 시작·종료한다.

관리 도구에서 `npm ci`, `npm test`, `npm run build`를 실행한다. 기존 분석 수입 통합 테스트는 `DOWNLOADS_DIR`의 보존된 GA4·GSC·Naver 원본 표본을 사용한다. 테스트 DB는 매번 별도 임시 폴더에 만든다.

Windows 로컬 배포는 `tools/guide-manager/scripts/deploy-local.ps1`을 사용한다. 대상 앱 이름·포트·진행 중 작업을 확인하고 SQLite 온라인 백업과 기존 소스 백업을 만든 뒤 코드와 의존성을 교체한다. 데이터 폴더·기존 키·가이드 원고는 배포 대상 코드와 분리되어 있다.

참고 구현 근거: [Nuxt prerender 설정](https://nuxt.com/docs/3.x/getting-started/prerendering), [Resend 멱등성 키](https://resend.com/docs/dashboard/emails/idempotency-keys).

운영 배포 확인: 2026-09-06, localhost:8788에 새 API·세션 방어·분석 자료 최신성 표시가 반영되었다. Chrome 자동 점검 탭은 ERR_BLOCKED_BY_CLIENT로 열리지 않아 데스크톱·모바일 시각 점검은 완료하지 못했다. 브라우저에서 실제 메일을 발송하는 시험도 수행하지 않았다.
